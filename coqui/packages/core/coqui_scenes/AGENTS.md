# coqui_scenes

One folder per scene (its set, its scene), and the pictures other features ask for.

- Kind: Flutter package.
- Replaces: `historia/escenas/*.js`, `pixel/*-set.html`, `miniatura` and `panelW`.
- One package is one lane. Branch: `lane/coqui_scenes/<order number>`, or `story/<n>` with `lane:coqui_story_checks` for a scene port.
- The runbook is `../../../AGENTS.md`. Read it first.
- This file holds standing rules only. What a ticket did goes in its PR body and its issue.

## May depend on

- The plan's row: pixel, contracts, ui.
- Coquí packages: `coqui_contracts`, `coqui_pixel`, `coqui_ui`.
- Third party: `material_ui` ^1.11.1 (and `collection`, allowed anywhere).
- Dev only: `flutter_lints`, `flutter_test` (from the SDK), and `coqui_testing` (the fakes).
- `coqui_testing` goes under `dev_dependencies` only. Tests and `tool/` import it. Nothing under `lib/` does.
- Material widgets come from `package:material_ui/material_ui.dart`. Nobody imports `package:flutter/material.dart`.
- Nothing else. A package that is not listed here is added by a request in `coqui/requests/`, not by you.
- `dart run tool/check_boundaries.dart` (at `coqui/`) fails the branch otherwise.

## Public surface

- `lib/coqui_scenes.dart` is the one public file. Everything else is under `lib/src/`.
- Nobody imports another package's `src/`.
- It exports:
  - `loadScene` (makes a scene from its sheet, read from this package's assets),
  - `convertedScenes` and `sceneRegistry`,
  - `SetScene` (a converted scene: its sheet, its engine, its set built from a key, its characters' shadows) and `SetBakes` (a scene's baked states, cached by set key),
  - `loadSheet` and `sheetAsset`,
  - `StillFrame` and `StillHost` (plus `frogOfCode`),
  - `PictureError`, and `ScenePictures` (plus `pictureF`), the `PictureSource` of page 12, section 3: `of(ref, {width = 196, height = 104, animated = false})`, sizes in PICTURE pixels, no scale.
- `lib/src/registry.dart` and `lib/src/converted_scenes.dart` are generated (and gitignored) by `dart run tool/make_scenes.dart` at `coqui/` from `lib/src/<id>/<id>.dart`. Never edit them by hand or commit them.

## Scene layout and porting rules

### Converted legacy scenes (places 1 to 3, `Sheet`)

- `lib/src/set_kit.dart` is the port of `docs/proyecto/pixel/set-kit.js`, shared by every set. A helper a new set reference adds to `set-kit.js` is ported here with the same name and parameters (additive only).
- `lib/src/cocina_kit.dart` is the port of `docs/proyecto/pixel/cocina-kit.js` (additive only; existing painters never change).
- Each scene lives in `lib/src/<id>/`:
  - `<id>_set.dart`: port of `<id>-set.html`, call for call (`<id>Engine()`, state class with `fromQuery`, `fromKey`, `key`, and `buildSet`).
  - `<id>_places.dart`: every screen place the scene uses, read from the sheet once and projected by the engine. No number of the sheet is typed in Dart.
  - `<id>_sprites.dart` (when the scene has its own sprites): scene-specific sprite makers.
  - `<id>.dart`: the old scene file ported line for line as an `Escena` implementing `SetScene` (and `SetOverSprites` / `PairPlaces` as needed), using the sheet's `moves`, `code`, `setKey`, `shadows`, and `remap`.
- `assets/sheets/<id>-sheet.json`: copy of `docs/proyecto/pixel/<id>-sheet.json`, maintained by `dart run tool/make_sheets.dart [--check]`.
- `coqui/ref/pp/<id>/`: baked reference states generated by `node coqui/tool/ref/pp/make.js` and indexed in `coqui/ref/pp/index.json`.

### New scenes (places 4 to 10, `SceneSheet`)

- There is no old scene file: the scene is written from its script's Needs list (`historia/notas/guiones/<id>.md`), its set ported call for call from `<id>-set.html`, and every place read from `<id>-sheet.json` via `coqui_pixel`'s `SceneSheet`.
- `sheet_cache.dart` reads sheets without `pairPicture` as `SceneSheet` (`sceneSheetOf(id)`); `sheetOf(id)` returns its `legacy()` `Sheet` for shared code.
- Shared place kits and cast files (such as `lib/src/colmado/`, `lib/src/calle/`, `lib/src/plaza/`, `lib/src/playa/`) have one first writer; later scenes in the same place add only and never alter existing output.
- Each scene's `fresh(story)` sets initial state from the story's acts; every act implements its Needs line using sheet spots, boxes, and groups only. Where the sheet names no place or the script leaves a picture unsettled, do the plainest thing that keeps the story playing and mark it `// OPEN:`.
- Sprite sheets for the content lane are generated by `tool/make_<id>_sprites_test.dart`.
- Play-every-path and sheet-rules checks live in `coqui/packages/coqui_story_checks/` (not in `feature_story`).

### Shared rendering, depth, shadows, and interaction rules

- **Randomness:** Any random draw uses the game's one `Rng` passed into the scene factory or host (`(host as dynamic).rng`), never a newly constructed RNG.
- **Depth and occlusion:** Sprites are composed against the set's depth (using live depth after `drawLeaves` when a set has swaying fronds or animated parts) with the sheet's upright plane (`front.plane`) and `front.bias`; between two sprites the nearer pixel wins (ties within `0.001` go to the later layer). A frame drawn with no set (`HeadlessRenderer`) skips set re-draw passes.
- **Shadows:** A character casts an engine shadow only when standing on a ground surface (never on a seat, elevated deck/surface, water with `WaterLook.noShade`, or at night when the set casts none) and only while more than half faded in (`al > .5`). Converted `SetScene` scenes set `frogShadow => false`.
- **Glints and water:** Sets with water glints leave them in `PpEngine.glints` (`BakedSet` preserves them) and draw them deterministically at wind time in `drawFrame` (still under reduced motion).
- **Touch boxes and HUD items:** Touch boxes of sprite things match their drawn pixels; set things use the sheet's boxes. Things drawn on the display (HUD) are hit-tested in display coordinates via `pictureToDisplay` / `displayToPicture` so their touch area stays identical at zoom 1 and zoom 2. Any thing whose touch box runs off the picture carries `Thing.hintBox` for its hint frame and twinkle.
- **Loose acts:** Acts started with `suelto: 1` run in the background while lines play, and `ya` waits for them.
- **Review picture names:** Review lookup folds accents and maps spaces to underscores via `sheetPictureName`.

## Pictures: by name, the size rule, old pictures until converted

`ScenePictures` (`lib/src/pictures.dart`) is the `PictureSource`. A `PictureRef` carries its scene, its state (`set`), and its `name`: `<word>.si` / `<word>.no` (`PictureRef.of`) or `nivel.<word>.<index>` (`PictureRef.ofLevel`).

- **Converted scenes (`convertedScenes`):** The picture of that name comes from the sheet (`pictures.<word>.<side>` or `level` entry for `nivel.<word>.<index>`). A ref with no name falls back to lookup by scene, state, and view through review pairs and fails clearly on ambiguity. Unknown names fail clearly. `test/pictures_test.dart` verifies every pair side and level picture requested by the course.
- **The size rule (`lib/src/picture_cut.dart`):** Sizes are in picture pixels (`width` x `height`). A review picture shows a `width / zoom` x `height / zoom` region of the 240 x 216 scene picture (zoom 1 or 2 from the sheet), centred on the sheet's `crop`, clamped inside the scene picture, scaled by whole-number `zoom x zoom` blocks (at 196 x 104 it equals the sheet's `crop`). A level-check cell (`nivel.<word>.<index>`) is always zoom 1 (96 x 106 region centred on the level entry's `crop`, clamped inside the picture). Any review size not divisible by whole zoom blocks throws `PictureError`; nothing is ever stretched by a fraction.
- **Unconverted scenes:** Scenes not in `convertedScenes` show their old pictures from `assets/old_pictures/<id>/index.json` through `PixelView` at their native size only (196 x 104 review, 96 x 106 level cell). `dart run tool/make_old_pictures.dart [--check]` keeps assets, `pubspec.yaml`, and fixtures in sync and fails if a folder remains for a converted scene or a required picture is missing.
- **Old-pictures tests:** Tests of the unconverted path use the test-only scene `prueba` (`test/support/fixtures/test_scene.dart` via `TestSceneBundle`) so converting real scenes never breaks them.
- **In-place picture replacement:** Replacing a picture widget in place (new ref, name, size, or `animated`) restarts cleanly using `TickerProviderStateMixin` (`test/pictures_test.dart`).

## Tools

Run in `coqui/packages/core/coqui_scenes` (except `make_scenes.dart`, which runs in `coqui/`):

```
dart run tool/make_scenes.dart [--check|--check-committed]   # in coqui/: generates shared scene lists and fixtures
dart run tool/make_sheets.dart [--check]                     # sheets as assets and browser test fixtures
dart run tool/make_old_pictures.dart [--check]               # old pictures for unconverted scenes
dart run tool/make_set_fixture.dart [--check]                # hashes of coqui/ref/pp/<scene>/ for browser set tests
dart run tool/make_sprite_fixture.dart [--check]             # hashes of coqui/ref/sprites/escenas/<scene>/
node tool/preview_shots.mjs --scene <id> --states DIR --out DIR [--fixture]
COQUI_PREVIEW_DIR=DIR COQUI_REPORT_DIR=DIR COQUI_SCENE=<id> flutter test tool/compare_all_test.dart
COQUI_OUT=DIR flutter test tool/make_<id>_sprites_test.dart  # sprite sheet for the content lane
COQUI_OUT=DIR flutter test tool/<id>_frames_test.dart        # act-by-act frames for fresh readers
flutter build web --release --no-web-resources-cdn -t tool/dev_main.dart; node tool/bake_time.mjs --scene <id>
```

Numbers for a report: `COQUI_REPORT_DIR=DIR flutter test` writes them on the VM; `--dart-define=COQUI_SHOW=true` makes comparison tests print their numbers.
